PR #91: artwork error recovery

PR #91 replaces the previous song's cover with the existing music-note placeholder when the next image fails. Pending loads keep the old cover until they settle. Reduce motion switches immediately. No layout or control changes.

Actual Windows native egui demo readbacks: baseline 8da79db, candidate 879d523. Both use the same temporary fixture: an old synthetic SVG seeded as the shown cover, a corrupt new PNG decoded by egui, and other demo artwork disabled. Fixture patches, source/binary hashes and all PNG hashes are in the evidence manifest. Capture fixtures were removed from the production sources.

All sixteen captures were inspected. Every before/after pair differs only in the same 56 × 56 cover square at (20, 688) through (76, 744); the rest of each full-window image is pixel-identical. These are frozen end states, not proof of live transition timing, natural network failure or Apple-account listening. The paint regression separately verifies old-texture release, immediate Reduce motion behavior and successful image retry.

This bug correction uses the existing fade and placeholder. It introduces no redesign, new dependency, account write, storage format or network destination. Hosted final-head checks, a qualified download and the remaining motion/release gates stay separate.
