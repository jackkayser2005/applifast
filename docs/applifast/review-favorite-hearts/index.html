Known Apple favorite hearts

Candidate fix/apple-favorite-hearts, baseline 4eb33e0 (PR #30). Filled hearts return to song rows and the player bar for exact Apple song identities whose current favorite flag is true. They are accessible read-only images, without favorite/unfavorite buttons. Unknown and non-favorite songs stay unmarked.

Matching Windows native captures use identical Apple demo data, Songs or Favorites, theme, window size, neutral pointer, zoom and Reduce motion. No real account data or playback is used. The maintainer explicitly requested restoring these indicators; this scope keeps the existing layout.

Regression tests cover exact library/catalog identity, false and unknown flags, current-library precedence, read-only accessible images and absence of favorite-write controls. Real-account refresh behavior and HTML browser rendering remain separate acceptance checks.

All 16 matching native captures were inspected. Formatting, strict default/demo Clippy, 1,006 default and 1,040 demo library tests (four opt-in checks ignored in each), binary/integration suites, default doctests, strict demo Rustdoc, the demo build, gettext and Node bridge/signer checks pass. Translation messages are unchanged. The launcher checker cannot complete here because Ruby is absent; optional projectM, site/Nix and non-Windows checks remain unverified. Existing intermittent persistence failures remain a separate release risk.
